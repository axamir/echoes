# data

Derived structured data for the Echoes project.

- [`emails.schema.json`](emails.schema.json) — JSON Schema for one email-thread record
- [`emails.json`](emails.json) — 91 records, one per archived thread PDF in [`../docs/emails/`](../docs/emails/)

## How `emails.json` is built

Generated by [`../analysis/scripts/build_emails_json.py`](../analysis/scripts/build_emails_json.py) from the extracted text in `docs/emails-text/`:

```bash
python3 analysis/scripts/build_emails_json.py
```

Each export is a whole Gmail thread, so the record describes the thread: its printed subject, the printed message count, and the **first** message's date, sender and `To:` line.

| Field | Filled | Source |
| --- | --- | --- |
| `date`, `date_raw` | 91/91 | First message header. `date` is the same value in ISO form. No timezone is stated in the export, so none is added. |
| `sender`, `recipients` | 91/91 | First message header and `To:` line |
| `subject`, `message_count` | 91/91 | Top of the export |
| `case_id` | 81/91 | Only when a Case ID appears in the subject line; otherwise `null` |
| `archive_case_folder` | 81/91 | The source archive's `CASES/<id>/` folder |
| `echo_label` | 91/91 | The source archive's `EchoN` folder |
| `sha256` | 91/91 | Computed from the PDF; matches `docs/emails/SHA256SUMS.txt` |
| `summary` | 0/91 | Left `null` on purpose. Write summaries by hand from the source. |

Do not invent values. If a field is not printed in the source, it stays `null`.

### Known differences you will see in the data

- Filename dates in the source archive sometimes differ from `date` (e.g. `Echo5/2025-07-17_narrative-followup_echo5-1` has `date` 2025-08-09). `date` comes from inside the file.
- Two PDFs in folder `500VU00000WBfn7YAD` have subject Case ID `500VU00000WBsdxYAD` (`case_id` ≠ `archive_case_folder`).
- Exact duplicate PDFs in the source are kept, so some records share a `sha256`.
